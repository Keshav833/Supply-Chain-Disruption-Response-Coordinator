#### Scenario 1: Supplier Delay (INC-1001)
- **Input**: Supplier SUP-01 delayed by 7 days; must fulfill 100 units within 10 days
- **Process**: 6 agents run in parallel (Monitor → Inventory/Supplier/Route/Cost → Coordinator)
- **Output**: REORDER decision from cheapest supplier; cost breakdown
- **Example Run**: ~100-150ms

#### Scenario 2: Route Blockage (INC-1002)
- **Input**: Route RT-NYC-MIA-01 blocked; must reroute 200 units within 5 days
- **Process**: Same 6-agent pipeline, Cost Agent ranks alternate routes
- **Output**: REROUTE decision via cheapest alternate; cost breakdown
- **Example Run**: ~100-150ms

#### Scenario 3: Invalid Incident (INC-1003)
- **Input**: Incomplete report (missing required original_supplier_id)
- **Process**: Monitor Agent validates and rejects
- **Output**: UNKNOWN decision with validation error message
- **Example Run**: ~10-20ms (fails fast)

#### Output Section
- Multi-agent execution trace (agent → tool → evidence section → status)
- Blackboard sections summary (all 6: incident_assessment, inventory_findings, supplier_findings, route_findings, cost_findings, mitigation_decision)
- Final decision with rationale and cost breakdown
- Execution metadata (Run ID, outcome, mode, duration)
- Demo log last 3 entries in structured format

#### Optional Live LLM Cell
- Marked clearly: "OPTIONAL: Live LLM Mode (Requires Valid API Key)"
- Skipped by default with clear instructions
- Can be enabled by setting `RUN_LIVE_LLM = True`
- Requires valid GEMINI_API_KEY or OPENAI_API_KEY
- Requires network access
